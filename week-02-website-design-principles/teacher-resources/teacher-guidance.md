# Week 2 Teacher Guidance – Website Design Principles

## Curriculum purpose

Week 2 develops the A1 website-design principles and prepares learners to satisfy A.P1 by comparing how two websites use design principles for their intended audience and purpose.

The main pedagogical progression is:

**identify a feature → name the principle → explain the effect → connect to audience/purpose → compare**

Do not allow the lesson to become a checklist of visual features. The key skill is explaining why a design choice matters.

## Specification coverage

Ensure the lesson includes:

- usability
- white space
- site layout
- accessibility
- spacing
- navigation
- typography
- alignment
- clarity
- consistency / intuitiveness
- accuracy
- content
- media
- simplicity

The specification presents these as examples of website-design principles. Learners should use the terminology accurately and apply it to evidence.

## Assessment boundary

BBC and Amazon are being used as the planned Assignment 1 comparator websites. Therefore:

- use a different website for detailed tutor modelling
- do not provide complete BBC/Amazon model paragraphs
- provide structure, prompts and questioning rather than assessment-ready wording
- learners should select and explain the evidence they intend to use

## Suggested modelling approach

Choose a familiar but non-assessment-specific website with clear navigation, layout, typography and accessibility features.

Model one principle using:

1. **Principle** – identify the relevant design principle.
2. **Evidence** – point to an observable feature.
3. **Effect** – explain what the feature helps the user do or understand.
4. **Audience** – explain why this matters to the intended users.
5. **Purpose** – explain how it contributes to the site's goal.

Then model a comparison between two neutral examples before learners apply the method to BBC/Amazon.

## Indicative retrieval answers

1. **Purpose:** what the website is intended to achieve, such as informing, selling, communicating or providing a service.
2. **Target audience:** the intended group of users the website is designed to serve.
3. User requirements could include being user-friendly, consistent, navigable, customisable or flexible.
4. Audiences have different goals, knowledge, needs and contexts, so design choices should support those differences.
5. **Usability:** how effectively and efficiently users can interact with a website and achieve their goals.
6. **White space:** intentionally unused space around/between elements; it does not have to be white.
7. Navigation examples include menus, hyperlinks, search, breadcrumbs, buttons and footer links.
8. Consistency makes controls and structures more predictable, reducing the amount users need to relearn.
9. Accessibility examples include readable text, sufficient contrast, meaningful alt text, keyboard access and clear labels.
10. **Typography:** the selection and arrangement of text, including typeface, size, weight, spacing and hierarchy.
11. Layout can establish hierarchy by making important content larger, more prominent or positioned earlier in the visual flow.
12. Simplicity means reducing unnecessary complexity while retaining what users need.
13. Tiny pale-grey text over a photo may affect typography/readability, clarity, accessibility and usability because contrast and legibility are poor.
14. Fixed placement of search, basket and account controls supports consistency, intuitiveness, navigation and usability.
15. “Good navigation” is an unsupported judgement. Strong evidence identifies the navigation feature and explains its effect for the intended audience/purpose.

## Guidance for the design-principles audit

Do not expect every principle to be equally important on every website. The audit is a vehicle for discussion about evidence and relevance.

Useful prompts:

- What exactly can you point to?
- What user task does this support?
- Who benefits from this choice?
- Is this always effective, or only in this context?
- Which other principle does this feature influence?

## Guidance for BBC/Amazon comparison

Learners should avoid producing two separate descriptions. Encourage direct comparisons such as:

- both websites use X, but for different reasons
- Website A prioritises X whereas Website B prioritises Y
- the difference reflects different user tasks
- a principle is implemented differently because the sites have different purposes

Do not dictate the specific comparison conclusions; these should arise from learners' own observations.

## Common weak responses and interventions

### “The website looks professional.”

Ask: Which visible feature creates that impression? Which design principle does it relate to? What effect does it have?

### “The navigation is easy.”

Ask: Easy to do what? Which navigation feature makes that task easier?

### “There is lots of white space.”

Ask: What does the spacing separate or emphasise? Does it improve scanning or hierarchy?

### “The site is accessible because it has images.”

Clarify that accessibility is about enabling people with different needs to perceive, understand and interact with the site. The presence of images alone does not make a site accessible.

### “Amazon is better because it has more content.”

Ask whether more content supports or obstructs the user's task. Require a link to purpose and audience.

## Adaptive teaching

### Support

- reduce initial focus to six core principles
- provide a visual glossary
- allow learners to speak answers before writing
- use sentence stems:
  - “The site uses…”
  - “This can be seen in…”
  - “This helps the user because…”
  - “This is suitable for the audience because…”
  - “In contrast…”
- provide a partially completed evidence grid

### Stretch

- ask learners to identify trade-offs between principles
- compare different viewport sizes
- distinguish novice and experienced user needs
- ask whether breaking a convention can ever improve communication
- require learners to justify which principles matter most for a particular purpose

## English, maths, EDI and employability

**English:** comparative writing, precise terminology, evidence selection, explanation and paragraph structure.

**Maths:** proportion, relative sizing, spacing, alignment and responsive dimensions.

**EDI:** inclusive design, accessibility and avoiding assumptions about users.

**Employability:** client-facing justification, evidence-based design critique and professional communication.

## End-of-session diagnostic

Learners are ready to progress when they can independently produce a statement that includes:

**specific design evidence + effect on user + audience/purpose connection + meaningful comparison**.

Carry forward any gaps into Week 3 retrieval and formative feedback.
