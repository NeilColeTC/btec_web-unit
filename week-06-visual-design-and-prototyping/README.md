# Week 6 – Visual Website Design and Prototyping

**W/B:** 12 October 2026  
**Duration:** 3 hours  
**Specification:** B1 – Website design  
**Assessment preparation:** B.P2, B.M2

## Curriculum intent

Develop learners' ability to turn the Week 5 client and user requirements into coherent visual website-design documentation.

The central progression is:

**requirements → structure → style → page layout → responsive variation → annotation → justification**

Learners should understand that a design document is not simply a collection of attractive sketches. Each design decision should be traceable to the intended audience, purpose, client requirements and usability needs.

## Learning outcomes

By the end of the session learners will be able to:

1. Explain the purpose of a site map, mood board and wireframe.
2. Produce a logical site map and navigation structure.
3. Develop a visual style direction using colour, typography, imagery and layout references.
4. Produce annotated wireframes for required website pages.
5. Consider desktop, tablet and mobile layouts.
6. Explain how visual design choices respond to client and user requirements.
7. Identify evidence that will contribute to B.P2 and later B.M2 justification.

## Core specification content

The session develops B1 content including:

- initial design ideas and prototypes
- storyboard, mood board, wireframe and site-map style documentation
- realistic representations
- alternative design thinking
- mobile/tablet compatibility
- application of website-design principles
- use of design documentation to meet client requirements

## Formative assessment

Use:

- retrieval questioning
- site-map review
- navigation-path testing
- mood-board rationale
- wireframe quality check
- responsive-design questioning
- annotation review
- requirement-to-design traceability
- retrieval quiz
- exit ticket

## Adaptive teaching

### Support

- provide a design-documentation glossary
- use a partially completed site-map example
- provide page-layout component prompts
- allow hand-drawn or digital wireframing
- provide annotation sentence stems
- use a requirements checklist beside design work

### Stretch

- require alternate navigation approaches
- compare mobile-first and desktop-first thinking
- justify trade-offs between visual richness and simplicity
- design for differing user priorities
- ask learners to explain how one decision supports several requirements at once

## Assessment boundary

The assignment requires learners to produce their own design documentation. Tutor modelling should therefore use a neutral or fictional non-assessment scenario for complete worked examples. For Hot Beans Web, provide process guidance, templates and questioning rather than completed page designs.
