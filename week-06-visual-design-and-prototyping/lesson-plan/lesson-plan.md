# Week 6 Lesson Plan – Visual Website Design and Prototyping

**W/B:** 12 October 2026  
**Duration:** 3 hours  
**Specification focus:** B1  
**Assessment preparation:** B.P2, B.M2

## Learning outcomes

Learners will be able to:

1. Explain the role of site maps, mood boards and wireframes.
2. Translate client requirements into a logical site structure.
3. Develop a visual style direction appropriate to audience and purpose.
4. Produce annotated wireframes for required pages.
5. Adapt page layouts for desktop, tablet and mobile contexts.
6. Link design decisions explicitly to user/client requirements.

## Key terminology

site map, navigation structure, information architecture, hierarchy, mood board, wireframe, prototype, layout, responsive design, breakpoint, viewport, mobile-first, desktop-first, annotation, requirement traceability, visual hierarchy, consistency, affordance.

## Teacher modelling

Use a neutral example such as a local museum, community event or fictional training provider.

### Site map modelling

Think aloud using:

1. What pages are needed?
2. Which page is the home/start point?
3. Which pages belong at the same hierarchy level?
4. Can users predict labels?
5. Can a user reach important content efficiently?
6. Does the structure support the site's purpose?

### Mood-board modelling

For each chosen visual reference, ask:

- what design quality does this suggest?
- why might that quality suit the audience?
- how could it influence colour, typography, imagery, spacing or tone?

### Wireframe modelling

Keep early wireframes low fidelity. Focus first on:

- header/navigation
- main content hierarchy
- calls to action
- images/media placeholders
- form placement where relevant
- footer/supporting navigation
- responsive rearrangement

## Adaptive teaching

### Support

- provide a component bank: header, navigation, hero, card, form, footer
- give page-purpose prompts
- allow paper sketches before digital versions
- provide annotation stems such as “I placed… because…” and “This supports requirement… by…”
- reduce the first wireframe to one key page before extending

### Stretch

- create two plausible navigation structures and justify one
- produce mobile-first and desktop-first alternatives
- analyse which content should be prioritised or deferred on smaller screens
- explain trade-offs between visual impact, accessibility and simplicity
- justify why a layout convention should be followed or intentionally broken

## English and mathematics

**English:** concise annotation, technical vocabulary, justification, audience-aware wording and precise labels.

**Mathematics:** proportion, spacing, alignment, grid relationships, relative dimensions and responsive scaling.

## EDI / British Values / employability

Build accessibility and inclusive design into visual decisions from the start rather than treating them as later corrections. Encourage respectful peer critique and recognition of diverse user needs. Link the process to professional UX/UI design, client communication, documentation and iterative development.

## Misconceptions to anticipate

- a site map is a sketch of a web page
- a mood board is only a collection of attractive images
- wireframes should contain final colours and finished graphics
- responsive design means shrinking the desktop page
- every page should have the same amount of content
- annotation means naming interface elements rather than explaining decisions
- a design is strong merely because it looks polished

## Assessment boundary

Learners must produce their own Hot Beans Web designs. Do not provide finished Hot Beans page wireframes, site maps or mood boards that could be submitted as assessment evidence. Tutor examples should demonstrate transferable process only.

## After the lesson

Check that each learner has a coherent site structure, a visual direction and at least an initial set of annotated page layouts. Identify gaps before Week 7, particularly missing requirements, weak responsive thinking and annotations that describe rather than justify.
