# Week 5 Lesson Plan – Client Requirements and Assignment 2

**W/B:** 5 October 2026  
**Duration:** 3 hours  
**Specification focus:** B1  
**Assessment preparation:** B.P2

## Learning outcomes

Learners will be able to:

1. Extract explicit client requirements from a vocational brief.
2. Distinguish client requirements from user needs.
3. Produce a clear problem definition statement.
4. Identify the intended audience and explain likely needs.
5. Identify constraints, benefits, interactivity and complexity.
6. Produce measurable success criteria.
7. Map requirements to planned design evidence.

## Key terminology

client brief, client requirement, user requirement, target audience, problem definition, constraint, benefit, functional requirement, non-functional requirement, interactivity, complexity, success criterion, fitness for purpose, design documentation.

## Teacher modelling

Use a neutral scenario such as a community sports club or local charity rather than Hot Beans Web for any fully worked example.

Model the sequence:

1. **What is the client trying to achieve?**
2. **Who is the intended audience?**
3. **What must the website contain or do?**
4. **What do users need to be able to do easily?**
5. **What constraints affect the design?**
6. **What benefits should the solution deliver?**
7. **How much interactivity/complexity is appropriate?**
8. **How will we know the solution is successful?**

## Adaptive teaching

### Support

- colour-code client, user and technical requirements
- provide sentence stems for problem definition
- give a partly completed requirement table
- allow paired discussion before drafting
- provide examples of vague versus measurable success criteria
- use tutor checkpoints before learners move on

### Stretch

- classify functional/non-functional requirements
- distinguish critical/desirable/optional requirements
- identify conflicts between requirements
- propose measurable accessibility and responsive-design criteria
- explain how requirements will influence later testing

## English and mathematics

**English:** extracting meaning from a vocational brief, summarising requirements accurately, formal problem-definition writing, precise technical vocabulary.

**Mathematics:** measurable criteria may include dimensions, responsive breakpoints, counts, timings and tolerances where appropriate.

## EDI / British Values / employability

Discuss inclusive audience analysis and avoiding assumptions about job applicants. Link accessibility and fair access to equality and professional web practice. Employability is embedded through client communication, requirement analysis, planning, accountability and evidence-based decision making.

## Misconceptions to anticipate

- client requirements and user requirements are identical
- every sensible idea can be treated as a client requirement
- constraints are only disadvantages
- success criteria can be vague statements such as “looks professional”
- more interactivity is always better
- the problem definition should describe the final visual design in detail

## Assessment boundary

The client brief is summative assessment material. Learners may be taught how to analyse a brief and structure design documentation, but must make and document their own decisions for Hot Beans Web.

## After the lesson

Check that each learner has a viable problem definition, identified audience, requirement set and measurable success criteria before Week 6 visual-design work begins.
