# Week 5 – Client Requirements and Assignment 2

**W/B:** 5 October 2026  
**Duration:** 3 hours  
**Specification:** B1 – Website design  
**Assessment preparation:** B.P2

## Curriculum intent

Week 5 marks the transition from analysing existing websites to designing a website in response to a client brief. Learners are introduced to the Hot Beans Web scenario and begin translating a vocational brief into a structured problem definition, intended audience, user/client requirements, constraints, benefits, interactivity requirements and measurable success criteria.

The core design-thinking sequence is:

**Client brief → problem definition → audience → requirements → constraints → success criteria → design evidence**

## Learning outcomes

By the end of the session learners will be able to:

1. Explain the purpose of a client brief.
2. Extract explicit requirements from the Hot Beans Web scenario.
3. Infer reasonable user requirements without inventing unsupported client requirements.
4. Produce a clear problem definition statement.
5. Identify the intended audience and explain its likely needs.
6. Identify technical, design and project constraints.
7. Explain likely benefits of a successful website solution.
8. Define suitable interactivity and complexity requirements.
9. Produce measurable success criteria to guide later design, testing and evaluation.
10. Begin B.P2 design documentation in an organised evidence structure.

## Core source requirements

The Assignment 2 brief requires a recruitment-focused section of the Hot Beans Web website containing:

- a profile of the company
- profiles of existing trainee web developers
- job specifications and required qualifications
- an online application form
- links to web development courses

The target audience is people who have completed relevant web-development training or qualifications and are now looking for employment as web developers.

## Formative assessment

Use:

- retrieval questioning
- annotated client brief
- requirement classification
- problem-definition review
- audience-needs questioning
- success-criteria quality check
- peer review
- exit ticket

## Adaptive teaching

### Support

- requirement-extraction table
- sentence stems for problem definition
- model distinction between client requirements and user needs
- worked examples from a neutral non-assessment scenario
- success-criteria checklist
- paired oral rehearsal before writing

### Stretch

- distinguish functional from non-functional requirements
- distinguish explicit from inferred requirements
- identify tensions between audience needs and client constraints
- propose measurable criteria for usability, responsiveness and accessibility
- justify which requirements are critical, desirable or optional

## Assessment boundary

Learners must produce their own design documentation for the assessed Hot Beans Web scenario. Tutor modelling should therefore use a different neutral client brief when showing complete examples. Structure, prompts and quality criteria may be provided, but completed Hot Beans Web design documentation should not be supplied.
