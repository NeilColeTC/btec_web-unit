# Week 10 – CSS and Responsive Design

**W/B:** 16 November 2026  
**Duration:** 3 hours  
**Specification focus:** B2 – Website development tools and techniques / C1 – Website development  
**Assessment preparation:** C.P4, with continued links to B.M2

## Curriculum intent

Week 10 develops the HTML work from Week 9 by introducing CSS as the technology responsible for presentation, layout and responsive adaptation.

Learners should understand the progression:

**semantic structure → presentation rules → layout system → responsive adaptation → accessibility check → test → justify**

The existing `stage-2-responsive-design` Hot Wheels exemplar is used as an object of investigation. Learners compare it with Stage 1 to identify what changed, which changes came from CSS rather than HTML, and why particular techniques were selected. They then return to their own reviewed designs and implement appropriate CSS independently.

## Learning outcomes

By the end of the session learners will be able to:

1. Explain the separation of HTML structure and CSS presentation.
2. Connect an external stylesheet to an HTML document.
3. Use selectors, declarations, properties and values accurately.
4. Apply the box model, spacing, typography, colour and reusable design values.
5. Explain appropriate uses of Flexbox and CSS Grid.
6. Make images and page layouts responsive.
7. Use media queries to adapt layouts when content requires it.
8. Provide visible hover and keyboard-focus states for interactive elements.
9. Test layouts across different viewport widths.
10. Apply selected CSS techniques to their own website rather than reproducing the exemplar mechanically.

## Core practical evidence

Learners should leave the session with:

- an external stylesheet linked to their HTML pages
- a consistent base visual system
- readable typography and spacing
- at least one purposeful layout technique
- responsive image behaviour
- evidence of responsive adaptation
- visible interactive states where appropriate
- browser-width testing notes
- explanations linking CSS decisions to their own design and user needs

## Exemplar use

Stage 2 deliberately preserves the recognisable Stage 1 HTML while moving most development into `style.css`. It demonstrates custom properties, box sizing, typography, Flexbox, Grid, responsive images, focus states, forms and media queries.

Its breakpoints at 800px and 560px are examples only. Learners should identify when **their own** content stops working well and choose responsive behaviour accordingly rather than copying breakpoint values.

## Formative assessment

Use:

- retrieval questions
- CSS syntax mini-checks
- box-model prediction
- Flexbox/Grid selection questions
- Stage 1 → Stage 2 comparison
- breakpoint experiment
- keyboard navigation check
- learner implementation review
- exit ticket

## Adaptive teaching

### Support

- CSS rule anatomy template
- selector/property/value matching activity
- box-model diagram
- small isolated Flexbox/Grid experiments before whole-page work
- starter troubleshooting checklist
- responsive testing width table
- prompts linking **design decision → CSS technique**

### Stretch

Ask learners to:

- explain specificity/cascade conflicts
- compare Grid and Flexbox for the same content
- choose content-led breakpoints rather than device labels
- use reusable custom properties consistently
- identify where modern CSS reduces the need for JavaScript
- evaluate trade-offs introduced by a responsive design decision

## Assessment boundary

The Hot Wheels Stage 2 files are worked teaching examples. Learners may inspect, modify and test them while learning, but their assessed Hot Beans website must implement their own reviewed design decisions, content, CSS and responsive behaviour.
