# Week 12 – Development, Compatibility & Implementation Evidence

**W/B:** 30 November 2026  
**Duration:** 3 hours  
**Specification focus:** Learning Aim C – website development  
**Assessment preparation:** implementation, compatibility and evidence quality

## Curriculum intent

Week 12 consolidates the implementation skills introduced in Weeks 9–11. Learners should now move from isolated HTML, CSS and JavaScript techniques toward a coherent working website that reflects their reviewed design and client requirements.

The emphasis is on disciplined development rather than simply adding more features.

Learners should understand the progression:

**requirement → implementation → test → issue → fix → retest → evidence**

The week also introduces compatibility as a development concern. A page that works in one browser or at one viewport size is not yet sufficiently tested.

## Learning outcomes

By the end of the session learners will be able to:

1. integrate HTML, CSS and JavaScript into a coherent multi-page website;
2. check implementation against reviewed design documentation;
3. identify functional and visual defects during development;
4. test pages at different viewport sizes and in more than one browser where available;
5. record meaningful implementation evidence rather than only final screenshots;
6. distinguish a defect, refinement and design change;
7. use a structured debugging process;
8. maintain traceability from requirement to implemented feature;
9. identify remaining development gaps before formal testing begins.

## Adaptive teaching

### Support

- reduce the audit to one page before scaling to the full website
- provide a fixed debugging sequence
- use a page-by-page checklist
- provide a requirement → evidence sentence frame
- pair learners for compatibility checks without sharing assessed solutions

### Stretch

Ask learners to:

- identify inconsistent behaviour across browsers/viewports
- explain why a defect occurs rather than only fixing it
- refactor repeated code where appropriate
- identify technical debt introduced by rushed implementation
- prioritise defects by severity and impact
- distinguish a necessary fix from an optional enhancement

## Assessment boundary

Tutors may model debugging, compatibility checking and evidence-recording methods using the Hot Wheels exemplar or a neutral example. Learners must implement and document their own Hot Beans website independently.
