# Week 13 – Formal Website Testing

**Unit:** Pearson BTEC Level 3 Unit 6 – Website Development  
**Learning Aim:** C – Develop a website to meet client requirements  
**Focus:** Systematic testing, defect evidence, retesting and assessment evidence  

## Week purpose

Week 13 moves learners from informal checking during development into a structured testing process. The emphasis is on creating evidence that shows the website has been tested systematically against requirements, that defects have been recorded honestly, and that changes have been retested.

The key workflow is:

> **requirement → planned test → expected result → actual result → defect → fix → retest → evidence**

## Learning outcomes

By the end of the session learners should be able to:

1. distinguish informal checking from formal testing;
2. create tests linked to requirements and features;
3. select appropriate normal, boundary and erroneous data;
4. define expected results before testing;
5. record actual results accurately;
6. identify and log defects rather than immediately hiding them;
7. retest changed features using comparable conditions;
8. test functionality, compatibility, usability, accessibility and responsive behaviour;
9. capture evidence that demonstrates improvement;
10. explain how testing influenced development decisions.

## Core testing categories

Learners should consider:

- navigation and links;
- content accuracy;
- responsive layout;
- forms and validation;
- JavaScript functionality;
- accessibility;
- browser/compatibility behaviour;
- performance;
- client/user requirements.

## Learning sequence

**retrieve → classify → plan → predict → execute → record → diagnose → fix → retest → evaluate**

## Assessment connection

The week is primarily preparation for and production of evidence toward **C.P5**, while also strengthening the quality of evidence needed for later optimisation and evaluation.

A strong testing record should make it possible for another person to understand:

- what was being tested;
- why it mattered;
- the condition or data used;
- what should have happened;
- what actually happened;
- what problem was found;
- what changed;
- whether the change solved the problem.

## Assessment boundary

The Hot Wheels exemplar may be used to model how testing is planned, executed and recorded. It must not become the learner's assessed test plan. Assessed tests must derive from the learner's own requirements, implementation and defects.
