# Test Plan Builder

## Purpose

Create a formal test plan for your own Hot Beans website.

Start from requirements and important features, not from a generic list of things to click.

## 3. Quality audit

For each test ask:

- [ ] Is the requirement/feature clear?
- [ ] Is the test reproducible?
- [ ] Is the data/condition specific?
- [ ] Is the expected result measurable/observable?
- [ ] Does the test add useful coverage?
- [ ] Is evidence possible to capture?

---

## 4. Coverage audit

Which important requirement currently has no test?

Which feature has too many low-value tests?

Which test would reveal the highest-risk problem for the intended user?

---

## 5. Prioritisation

Mark each test:

- **High** – essential requirement or major user journey;
- **Medium** – important supporting feature;
- **Low** – useful but not critical.

Explain one priority decision.

---

## 6. Before execution

Do not fill in actual results yet.

A formal test plan should define success **before** you know the outcome.
