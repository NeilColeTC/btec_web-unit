# Week 13 – Testing Evidence Checklist

Use this as a formative audit before moving into optimisation.

## Test-plan quality

- [ ] My tests are based on my own requirements/features.
- [ ] Each test has a clear ID.
- [ ] The method/condition is specific enough to reproduce.
- [ ] Expected results were defined before execution.
- [ ] I have included a sensible range of test categories.
- [ ] I have used normal/boundary/erroneous data where relevant.

## Test execution

- [ ] I recorded actual results accurately.
- [ ] I did not convert every weak result into a pass.
- [ ] I captured evidence for important tests.
- [ ] I checked more than one viewport size.
- [ ] I checked navigation and required content.
- [ ] I checked forms/validation where applicable.
- [ ] I checked interactive JavaScript where applicable.
- [ ] I checked keyboard/accessibility behaviour.
- [ ] I checked compatibility using the browsers/devices available to me.

## Defects and improvements

- [ ] Genuine defects are recorded before they are fixed.
- [ ] Defect descriptions are reproducible.
- [ ] I identified likely causes rather than only symptoms.
- [ ] I recorded the change made.
- [ ] I retested using the same or equivalent condition.
- [ ] I retained before/after evidence.
- [ ] I considered whether a fix affected another feature.

## Requirement coverage

- [ ] Every essential client requirement has relevant testing evidence.
- [ ] My highest-priority user journeys have been tested.
- [ ] I can identify any remaining gaps or unresolved issues honestly.
