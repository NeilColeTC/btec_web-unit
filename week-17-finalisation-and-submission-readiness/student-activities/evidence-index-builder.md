# Evidence Index Builder

## Purpose

Create a clear map of your final evidence so another person can find and understand it without guessing.

This activity organises **existing authentic evidence**. It does not create replacement historical evidence.

## Suggested evidence groups

### Requirements and planning

Possible evidence:

- requirements analysis;
- success criteria;
- constraints;
- intended audience analysis.

### Design

Possible evidence:

- site map;
- mood board;
- wireframes;
- responsive designs;
- alternative design ideas;
- technical documentation;
- asset plan;
- scripting plans.

### Review and justification

Possible evidence:

- review records;
- feedback;
- accept/adapt/reject decisions;
- before/after design refinements;
- design justification.

### Implementation

Possible evidence:

- HTML/CSS/JavaScript files;
- screenshots;
- code extracts;
- implementation notes;
- version history where relevant.

### Testing

Possible evidence:

- formal test plan;
- expected/actual results;
- compatibility checks;
- accessibility checks;
- normal/boundary/erroneous data;
- defect records.

### Refinement and optimisation

Possible evidence:

- issue evidence;
- alternatives considered;
- change record;
- before/after evidence;
- retest and regression evidence.

### Evaluation

Possible evidence:

- requirement-linked judgement;
- strengths/limitations;
- feedback evaluation;
- technical evaluation;
- final conclusion.

### Professional practice

Possible evidence:

- planning and prioritisation;
- evidence of decision ownership;
- self-management reflection;
- debugging/problem-solving trail;
- final submission-readiness check.

---

## Evidence quality audit

For each important evidence item ask:

- [ ] Is the purpose of the evidence obvious?
- [ ] Is it my own work/evidence?
- [ ] Is it readable?
- [ ] Is the relevant part identifiable?
- [ ] Does it support the claim I attach to it?
- [ ] Is the file/version correct?
- [ ] Is it duplicated unnecessarily?
