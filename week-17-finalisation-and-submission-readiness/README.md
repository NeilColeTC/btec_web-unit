# Week 17 – Finalisation & Submission Readiness

**Unit:** Pearson BTEC Level 3 Unit 6 – Website Development  
**Learning Aims:** B and C  
**Focus:** Final verification, evidence organisation, technical checks, submission readiness and professional reflection

## Week purpose

Week 17 is the controlled close-down of the project. Learners should not treat the final session as an opportunity to redesign the website or add speculative new features. The priority is to make sure the work already completed is coherent, traceable, functional, evidenced and ready to submit.

The core workflow is:

> **verify → organise → repair only where justified → retest → cross-check → package → submit**

The central professional principle is:

> **Do not create new risk at the point of submission.**

## Learning outcomes

By the end of the session learners should be able to:

1. verify that all major client requirements are represented in the final solution;
2. confirm that the final website files open correctly and required pages/assets are present;
3. distinguish an essential final correction from unnecessary feature creep;
4. perform final regression checks after any justified late correction;
5. audit evidence against design, development, testing, optimisation and evaluation requirements;
6. organise evidence so that decisions and outcomes can be followed clearly;
7. identify genuine evidence gaps without fabricating historical evidence;
8. check naming, file structure, links and submission packaging;
9. write a concise final professional reflection based on the completed process;
10. complete a final submission-readiness sign-off.

## Final-week rule

Only make a late technical change when all three conditions are true:

1. there is clear evidence of a real issue;
2. the issue materially affects a requirement, usability, accessibility or functionality;
3. there is enough time to retest the changed area and relevant regression points.

If those conditions are not met, record the limitation accurately rather than introducing new instability.

## Learning sequence

**retrieve → requirements check → technical smoke test → evidence audit → controlled correction → retest → submission packaging → final reflection → sign-off**

## Assessment connection

Week 17 does not create replacement evidence for work that was never done. It helps learners present and verify authentic evidence already produced across the project.

The repository assessment boundary remains in force: the Hot Wheels exemplar may support understanding of techniques and process, but the submitted Hot Beans design, implementation, testing, optimisation and evaluation must remain the learner's own work.

## End state

A submission-ready learner should be able to answer:

- What did the client require?
- Where is each requirement implemented?
- Where is the evidence?
- What did testing reveal?
- What changed because of testing or feedback?
- What limitations remain?
- What files am I actually submitting?
- Can another person follow the evidence without guessing?
