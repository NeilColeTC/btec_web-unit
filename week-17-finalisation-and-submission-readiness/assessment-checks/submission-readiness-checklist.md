# Week 17 Submission Readiness Checklist

Use this only when the final submission copy has been created.

## Client requirements

- [ ] I have checked the final website against the major client requirements.
- [ ] I can identify where each major requirement is implemented.
- [ ] I can identify evidence supporting each major requirement.
- [ ] I have not hidden known limitations behind unsupported claims.

## Website technical checks

- [ ] The intended home/start page opens from the submission folder.
- [ ] All required pages are present.
- [ ] Navigation links reach the intended destination.
- [ ] Required images/media load correctly.
- [ ] CSS files are included and load correctly.
- [ ] JavaScript files are included and required interactions work.
- [ ] The application/contact form behaves as expected within the project scope.
- [ ] Important functionality can be operated by keyboard where appropriate.
- [ ] Responsive behaviour has been checked at representative widths.
- [ ] No critical dependency points to a file outside the submission folder.

## Final corrections

- [ ] Any late correction addressed a genuine evidenced issue.
- [ ] The smallest appropriate change was made.
- [ ] The original failed check was repeated.
- [ ] Relevant regression checks were completed.
- [ ] Evidence of the final correction/retest has been preserved where appropriate.
- [ ] I have avoided adding unnecessary new features.

## Evidence organisation

- [ ] Requirements/planning evidence is easy to locate.
- [ ] Design evidence is easy to locate.
- [ ] Review/feedback evidence is easy to locate.
- [ ] Implementation evidence is easy to locate.
- [ ] Formal testing evidence is easy to locate.
- [ ] Defect/retest evidence is easy to locate.
- [ ] Optimisation/refinement evidence is easy to locate.
- [ ] Evaluation evidence is easy to locate.
- [ ] Professional-practice reflection is easy to locate.
- [ ] Important evidence files have meaningful names.
- [ ] Duplicate/irrelevant temporary files have been removed where appropriate.

## Evidence integrity

- [ ] I have not fabricated historical screenshots, tests, feedback or development stages.
- [ ] I have not represented the Hot Wheels exemplar as my assessed Hot Beans work.
- [ ] Where evidence is genuinely absent, I have not disguised the gap.
- [ ] Claims in my evaluation are consistent with the evidence actually available.

## Evaluation

- [ ] Major judgements are linked to client requirements/user needs.
- [ ] Major claims use specific project evidence.
- [ ] I acknowledge genuine limitations and trade-offs.
- [ ] Compatibility/performance claims do not exceed what I actually tested.
- [ ] My final conclusion states how successfully the solution meets the brief and purpose.

## Submission packaging

- [ ] I am submitting the intended final version.
- [ ] The file/folder structure is understandable.
- [ ] The website can be opened without my normal editor configuration.
- [ ] The evidence files can be opened/read.
- [ ] I have checked the required submission method/location.
- [ ] I have retained a safe copy of the final submitted version where centre policy permits.
