# Specification Mapping – Teacher Notes

## Purpose

This document maps the teaching exemplar to relevant **Learning Aim B and Learning Aim C content** in the supplied Pearson Unit 6 specification.

It is a curriculum map, **not a claim that studying or completing the exemplar achieves assessment criteria**. Learners must generate their own evidence in response to the approved assignment.

## Learning Aim B – Design a website to meet client requirements

### B1 Website design

The specification includes:

- intended audience, problem definition, constraints, benefits, interactivity and complexity
- purpose requirements defined by a client brief
- design principles
- initial and alternative designs/prototypes
- mobile/tablet compatibility
- scripting design tools such as pseudocode and flowcharts
- ready-made/original assets
- feedback and refinement
- testing plans
- technical/design constraints
- legal and ethical considerations

### Exemplar support

The repository supports discussion of B1 through:

- `client-brief/hot-wheels-exemplar-brief.md`, which gives the exemplar an audience, purpose, requirements and constraints
- the three progressive versions, which allow learners to infer and critique implementation decisions
- learner testing/optimisation examples, which model the relationship between evidence, feedback and refinement
- the assessment-boundary materials, which require learners to undertake their own assessed design work

The repository deliberately does **not** provide Hot Beans wireframes, site maps, pseudocode, flowcharts or completed technical documentation.

### B2 Common tools and techniques

The specification identifies HTML/HTML5, forms, navigation, hyperlinks, interactive components, colour/styles/templates, CSS, multimedia/digital assets, accessibility, W3C standards, platform compatibility and suitable asset formats.

The exemplar demonstrates:

| Content/technique | Exemplar location |
|---|---|
| HTML5 structure | Stage 1 onwards |
| Navigation/internal links | Stage 1 onwards |
| External hyperlink | Stage 1 Services |
| Images and alternative text | Stage 1 onwards |
| Form controls | Stage 1 Contact |
| External CSS | Stage 2 onwards |
| Colour, spacing, borders, typography | Stage 2 onwards |
| Flexbox | Stage 2 onwards |
| CSS Grid | Stage 2 onwards |
| Responsive design/media queries | Stage 2 onwards |
| Keyboard focus states | Stage 2 onwards |
| Interactive controls | Stage 3 |

## Learning Aim C – Develop a website to meet client requirements

### C1 Client-side scripting languages

The specification includes original client-side scripts, JavaScript uses such as input validation/form handling, and constructs including syntax, loops, decisions, functions, parameter passing, events and methods.

Stage 3 demonstrates:

- functions and return values
- parameter passing
- `if / else` decision making
- event listeners
- methods
- arrays and iteration using `forEach`
- form handling and client-side validation
- DOM selection/manipulation
- browser storage using `localStorage`

The exemplar should be used to identify constructs and discuss their suitability. Learners' assessed scripting must arise from their own solution.

### C2 Website development

The specification includes CSS, original client-side scripting, mobile/tablet compatibility, effective use of tools/techniques and uploading to a web server/host.

The three stages model progressive development from HTML through CSS/responsiveness to JavaScript. Repository hosting/version control can support discussion of publishing and development practice, but learners still need evidence appropriate to their own assessed work.

### C3 Website review

The specification expects review against similar websites, purpose/audience, client requirements including optimisation, legal/ethical constraints, strengths and improvements.

Learner resources prompt critique of exemplar decisions and alternatives, but the assessed review must concern the learner's own website.

### C4 Website optimisation

The specification includes:

- performance and user testing
- feedback
- checking interactivity
- checking compatibility
- refinements/improvements to meet client needs

`learner-resources/testing-example.md` and `optimisation-example.md` model:

**requirement → test → evidence → issue → change → retest → conclusion**

They intentionally use the Hot Wheels exemplar rather than supplying assessed Hot Beans evidence.

### C5 Skills, knowledge and behaviours

The specification includes planning/recording, targets/timescales, gathering feedback, responding to outcomes, professionalism, accountability, individual responsibility and evaluation.

Meaningful Git/GitHub use can help learners understand progressive recording and version history. It should supplement, rather than replace, the evidence required by the approved assignment.

## Assessment criteria relationship

The approved B/C assignment assesses:

- B.P2
- B.P3
- B.M2
- C.P4
- C.P5
- C.P6
- C.M3
- BC.D2
- BC.D3

The exemplar teaches underpinning knowledge/processes. It does not pre-complete evidence for these criteria.
