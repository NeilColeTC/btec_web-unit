# Suggested Teaching Sequence – Teacher Notes

## Principle

Use the Hot Wheels site as an **example to interrogate**, not a foundation that learners rename and adapt into Hot Beans.

A useful overall sequence is:

**investigate → experiment → modify → test → critique → design Hot Beans independently → select techniques → develop → test → optimise → evaluate**

## Phase 1 – Investigate

Use existing professional websites to revisit purpose, audience and design principles.

Learners should be asking why a website has been designed in a particular way, not merely listing features.

## Phase 2 – HTML experiments

Before showing a polished site, use small tasks to practise:

- document structure
- headings and paragraphs
- lists
- links
- images/alternative text
- forms and labels
- semantic elements

## Phase 3 – Stage 1 exemplar

Introduce `stage-1-html-foundation`.

Suggested activities:

- identify semantic elements
- trace navigation between pages
- inspect metadata
- critique heading hierarchy and image alternative text
- modify content locally and observe the effect
- predict what CSS will need to solve

Emphasise the separation between content/structure and presentation.

## Phase 4 – CSS experiments

Practise individual techniques outside the assessed project:

- selectors
- box model
- typography
- custom properties
- Flexbox
- Grid
- responsive images
- media queries
- focus/hover states

## Phase 5 – Stage 2 comparison

Compare Stage 1 and Stage 2.

Questions should focus on decisions:

- Which HTML changed?
- Which visual changes came entirely from CSS?
- Why was Grid selected for the gallery?
- Where is Flexbox appropriate?
- When does the layout need to adapt?
- Why should breakpoints be content-led rather than copied blindly?

## Phase 6 – JavaScript experiments

Use small exercises to teach:

- variables/constants
- functions
- parameters
- decisions
- arrays
- iteration
- events
- DOM methods
- form handling

## Phase 7 – Stage 3 comparison

Inspect how JavaScript has been added to the existing responsive site.

For each feature ask:

1. What user/interface problem is being addressed?
2. Why is JavaScript suitable?
3. Which constructs are used?
4. What test data/conditions would be appropriate?
5. What could go wrong?
6. Would the feature be suitable for every website?

## Phase 8 – Testing and optimisation demonstration

Use the Hot Wheels testing and optimisation resources.

Make the distinction between:

- discovering a genuine issue
- recording evidence
- making a justified change
- retesting
- claiming an improvement without evidence

## Phase 9 – Deliberate exemplar boundary

At this point, stop developing Hot Wheels.

Learners return to the approved Hot Beans client brief and begin their own interpretation.

Avoid displaying a completed Hot Beans design alongside the exemplar.

## Phase 10 – Independent design

Learners identify requirements and produce their own design documentation, alternatives and technical planning. Feedback should inform their decisions.

## Phase 11 – Independent development

Learners select techniques appropriate to their own solution. Encourage them to explain why a technique was chosen rather than asking whether they have copied every exemplar feature.

## Phase 12 – Testing, optimisation and evaluation

Learners test their own functionality, compatibility and usability; gather feedback; respond to genuine issues; retain before/after evidence; and evaluate the optimised outcome against client requirements.

## Differentiation

The breadth of the exemplar allows different learners to engage at different depths.

A learner who needs support can trace and modify a single technique during teaching. A more confident learner can compare alternatives, refactor code, identify limitations or propose a different implementation.

The assessed solution should still represent each learner's own response.
