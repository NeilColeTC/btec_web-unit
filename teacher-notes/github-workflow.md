# Git and GitHub Workflow – Teacher Notes

## Purpose

Git/GitHub is used here to make development progression visible and to model meaningful version control.

It is not included simply so learners can produce a large number of commits.

## Exemplar repository history

Prefer commits that describe a meaningful development step, for example:

```text
Create semantic five-page HTML structure
Add accessible images and navigation
Add example HTML form controls
Introduce external stylesheet
Apply typography, colour and spacing
Add responsive Flexbox and Grid layouts
Add mobile media queries
Add time-based greeting
Add client-side form validation
Add persistent theme preference
Add responsive menu interaction
Refine navigation following testing
Document optimisation and retest
```

Avoid histories dominated by messages such as:

```text
update
changes
final
final2
fixed
```

## Suggested learner workflow

Learners can be encouraged to:

1. create/clone their own project repository where local policy permits
2. make an initial commit at a meaningful starting point
3. work in small, understandable development steps
4. test before committing significant changes
5. use commit messages that describe what changed
6. push regularly so work is backed up
7. retain earlier states rather than overwriting all evidence
8. use history/diffs when reflecting on development and optimisation

## Version-control discussion points

Ask learners:

- What changed in this commit?
- Why was it changed?
- Which requirement or test result influenced it?
- Could the previous version be recovered?
- Does the commit combine too many unrelated changes?
- Can the diff help explain before/after development?

## Optimisation evidence

A useful optimisation sequence might be:

```text
Implement responsive navigation
Record mobile navigation test issue
Refine narrow-screen navigation
Retest responsive navigation
```

The commit history can support the development narrative, but screenshots/test records may still be required to clearly evidence outcomes.

## Branches

Branches can be introduced if useful, but are not necessary for the teaching exemplar. The priority is understanding progressive version control rather than adding workflow complexity for its own sake.

## Assessment caution

Do not infer criterion achievement simply from commit quantity.

A strong history can support evidence of planning, progressive development and responding to issues, but assessment still depends on the learner meeting the requirements of the approved assignment and unit criteria.
