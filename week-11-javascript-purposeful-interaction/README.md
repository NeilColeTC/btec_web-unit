# Week 11 – JavaScript & Purposeful Interaction

**Unit:** Pearson BTEC Level 3 Unit 6 – Website Development  
**Learning Aim:** C – Develop a website to meet client requirements  
**Focus:** Client-side scripting, purposeful interaction and implementation  

## Week purpose

Week 11 extends learners' HTML and CSS work by introducing client-side JavaScript as a tool for solving specific user-interface problems. The session uses the existing **Stage 3 – JavaScript & Refinement** Hot Wheels exemplar for investigation, while learners implement original scripting decisions in their own Hot Beans websites.

The central question is not *How much JavaScript can I add?* but:

> **What user need or functional requirement does this script solve?**

## Learning outcomes

By the end of the session learners should be able to:

1. explain the role of client-side JavaScript alongside HTML and CSS;
2. identify events, functions, parameters, return values, selection, arrays and iteration in working code;
3. select DOM elements and change content, attributes or classes;
4. explain event-driven programming in a browser;
5. implement a small purposeful interactive feature;
6. describe how client-side validation improves feedback but does not replace server-side validation;
7. test JavaScript using normal, boundary and erroneous inputs;
8. explain how accessibility and progressive enhancement affect scripting decisions;
9. relate implementation choices back to reviewed designs and client/user requirements.

## Curriculum sequence

The staged exemplar now forms a visible development progression:

- **Stage 1:** HTML structure and meaning
- **Stage 2:** CSS presentation and responsive layout
- **Stage 3:** JavaScript behaviour, validation, persistence and refinement

Stage 3 demonstrates a time-based greeting, persistent theme preference, responsive hamburger navigation, client-side form validation and a scroll-to-top control.

## Key concepts

- JavaScript and client-side scripting
- DOM
- `DOMContentLoaded`
- variables and constants
- functions
- parameters and arguments
- return values
- `if / else if / else`
- events and event listeners
- DOM selection
- `textContent`
- attributes
- classes and `classList`
- arrays
- iteration / `forEach`
- form events
- `preventDefault()`
- validation and user feedback
- `localStorage`
- state and persistence
- accessibility state such as `aria-expanded`
- progressive enhancement
- testing and debugging

## Learning sequence

**retrieve → trace → experiment → investigate → design → implement → test → explain**

Learners first trace small examples, then modify controlled scripts. They subsequently interrogate Stage 3 to determine why each feature exists and which programming constructs make it work. Only after this investigation do they return to their own Hot Beans implementation.

## Assessment connection

This session supports development of the client-side scripting and implementation evidence required within Learning Aim C. Learners should retain evidence of their own code, testing, problems encountered and refinements.

The exemplar must not become assessed code. Learners should be able to explain why each script in their own solution exists and how it meets a requirement or user need.
