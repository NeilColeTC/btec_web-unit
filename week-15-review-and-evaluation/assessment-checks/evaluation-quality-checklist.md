# Week 15 Evaluation Quality Checklist

Use this before considering the final evaluation complete.

## Requirement coverage

- [ ] I evaluate the final website against the most important client requirements.
- [ ] I consider intended audience and purpose.
- [ ] I distinguish between requirements fully met, partly met and not met.

## Evidence

- [ ] Major claims are supported by evidence from my own project.
- [ ] I use test results rather than simply stating that testing occurred.
- [ ] I use relevant user feedback where available.
- [ ] I use before/after and retest evidence for refinements.
- [ ] I do not claim compatibility/performance beyond what I actually tested.

## Evaluation quality

- [ ] I make judgements rather than only describing features.
- [ ] I explain consequences for the user/client.
- [ ] I identify meaningful strengths.
- [ ] I acknowledge genuine limitations.
- [ ] I discuss realistic alternatives where useful.
- [ ] I recognise trade-offs rather than presenting every choice as perfect.
- [ ] I reach supported “on balance” conclusions.

## Technical areas

- [ ] navigation and information structure;
- [ ] responsive behaviour;
- [ ] accessibility;
- [ ] visual consistency and content/media;
- [ ] forms and interactive functionality;
- [ ] client-side scripting where used;
- [ ] browser/device compatibility;
- [ ] performance where evidence exists.

## Development process

- [ ] I explain how testing influenced development.
- [ ] I evaluate at least one optimisation/refinement.
- [ ] I reflect on effective working practices.
- [ ] I identify practices I would improve in future.

## Final conclusion

- [ ] My conclusion answers how successfully the website meets the client requirements and intended purpose.
- [ ] It uses my strongest evidence.
- [ ] It acknowledges the most important remaining limitation.
- [ ] It does not introduce unsupported claims.

## Red flags

Check that I have avoided:

- [ ] “good”, “professional”, “easy to use” without evidence;
- [ ] feature lists presented as evaluation;
- [ ] claiming “all browsers/devices” when only some were tested;
- [ ] saying “users liked it” without explaining who, what and why;
- [ ] inventing quantitative improvements without measurements;
- [ ] pretending the solution has no limitations.
