# Week 4 – Website Performance and Evaluation

**W/B:** 28 September 2026  
**Duration:** 3 hours  
**Specification:** A2 with consolidation of A1  
**Assessment preparation:** A.P1, A.M1, A.D1

## Curriculum intent

Week 4 completes Learning Aim A teaching by bringing together website design, performance and organisational impact. Learners move explicitly through the progression:

**compare → analyse → evaluate**

The session should help learners understand that website quality is not determined by appearance alone. A strong evaluation considers design principles, technical performance, user/client requirements, organisational consequences and the balance between strengths and limitations.

## Learning outcomes

By the end of the session learners will be able to:

1. Explain key server-side and client-side factors affecting website performance.
2. Explain how bandwidth, number of hits, file types, upload/download speed, browser, cache memory, processor speed and interactivity can affect user experience.
3. Analyse links between design choices and technical performance.
4. Analyse how performance influences suitability for audience and purpose.
5. Evaluate positive and negative organisational impacts of website design and performance.
6. Produce balanced evaluative conclusions supported by specific evidence.
7. Review their Assignment 1 evidence against A.P1, A.M1 and A.D1 expectations.

## Specification focus

### A2 – Factors affecting website performance

- where scripts run: server-side or client-side
- browser compliance
- server-side factors: bandwidth availability, number of hits and file types
- client-side factors: upload/download speeds, browser, cache memory, processor speed and interactivity

### Consolidated A1

Learners should continue applying website-design principles, media choices, creativity, SEO and intended audience/purpose when judging overall effectiveness.

## Formative assessment

Use:

- retrieval questions
- scenario responses
- performance-factor classification
- cause-and-effect explanations
- organisational-impact analysis
- comparison-to-evaluation writing
- peer review
- A.P1/A.M1/A.D1 evidence checklist
- exit ticket

## Adaptive teaching

### Support

- split performance factors into server-side and client-side categories
- use simple cause/effect chains
- provide sentence stems for analysis and evaluation
- allow oral rehearsal before writing
- use a structured evidence grid
- provide an evaluative conclusion framework

### Stretch

- analyse trade-offs between visual richness and performance
- distinguish correlation from direct cause when evaluating performance
- consider different user contexts, devices and network conditions
- identify situations where a technically slower page could still meet client requirements
- produce weighted judgements rather than lists of strengths and weaknesses

## Assessment boundary

Detailed teacher modelling should use non-assessment websites. BBC and Amazon remain learner-owned evidence sources. Provide structures, questions and exemplars of reasoning, but not complete assignment-ready evaluations.
