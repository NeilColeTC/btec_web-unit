# Stage 3 – JavaScript & Refinement

## Purpose

Stage 3 develops the **same website from Stages 1 and 2** by adding purposeful client-side JavaScript and interface refinements.

It is a **worked teaching exemplar**, not starter code for the assessed Hot Beans Web website.

## Progression

- **Stage 1:** HTML structure and content
- **Stage 2:** external CSS and responsive presentation
- **Stage 3:** client-side behaviour, validation, persistence and refinement

The intention is that learners compare versions and examine *why* a technique was introduced, rather than copy the finished website into their assessed project.

## JavaScript features

### 1. Time-based greeting
Demonstrates:
- functions
- a parameter
- return values
- `if / else if / else`
- the `Date` object
- DOM text updates

### 2. Persistent theme preference
Demonstrates:
- events
- classes
- functions and parameters
- `localStorage`
- DOM attributes
- state/persistence

### 3. Responsive hamburger navigation
Demonstrates:
- click events
- DOM selection
- class toggling
- accessibility state with `aria-expanded`
- coordination between JavaScript and CSS

### 4. Client-side form validation
Demonstrates:
- form events
- preventing default submission
- functions
- parameters and return values
- arrays
- iteration with `forEach`
- decision making
- string methods
- DOM creation/manipulation
- user feedback

The form is deliberately a demonstration only: no personal data is transmitted or stored.

### 5. Scroll-to-top control
Demonstrates:
- scroll events
- a nested helper function
- conditional class state
- smooth scrolling

## Accessibility refinements

JavaScript-enhanced controls include accessible names and state where appropriate. The form feedback uses an `aria-live` status region. Keyboard focus styling from Stage 2 is retained.

## Suggested teaching activity

Compare the same feature across stages and ask:

1. What problem or user need does the feature address?
2. Why is JavaScript appropriate for this feature?
3. Which programming constructs can you identify?
4. What test data would you use?
5. What could fail?
6. How would you test the feature on different browsers/devices?
7. Would this feature be appropriate for a different client's website? Why?

## Testing and optimisation

Stage 3 is suitable for demonstrating the next part of the development process:

**test → record evidence → identify an issue → make a justified refinement → retest → compare before/after**

The exemplar should be used to model that process. Learners' assessed testing and optimisation evidence must arise from their own website.

## Assessment boundary

Do not convert this website into the assessed Hot Beans Web solution.

For the assessed project, learners should interpret the client requirements, create and review their own designs, choose appropriate techniques, produce original client-side scripting, test their own solution, respond to evidence and feedback, optimise it, and evaluate the resulting website.
