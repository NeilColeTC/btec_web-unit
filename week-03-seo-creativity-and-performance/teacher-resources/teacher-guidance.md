# Week 3 Teacher Guidance – Creativity, Media, SEO and Performance

## Curriculum purpose

Week 3 bridges A1 design principles and A2 performance factors. The key progression is from identifying design features towards analysing the consequences of those choices.

Use the reasoning chain:

**evidence → effect → why → audience/purpose → performance/visibility implication**

The lesson should not become a list of SEO definitions or isolated technical facts. Learners should understand how design and technical choices interact.

## Assessment boundary

BBC and Amazon are the planned Assignment 1 comparison websites.

Therefore:

- use a different website for detailed modelling
- do not provide completed BBC/Amazon analytical paragraphs
- learners must identify their own evidence and construct their own conclusions
- teacher feedback should focus on quality of reasoning rather than dictating content

## Indicative retrieval answers

1. **Purpose:** what the site is intended to achieve.
2. **Target audience:** the group the site is primarily designed for.
3. **Usability:** how effectively and efficiently users can achieve goals.
4. Consistent navigation improves predictability and reduces relearning.
5. **White space:** intentionally unused space separating or grouping elements.
6. Examples: readable text, adequate contrast, scalable text, meaningful labels.
7. Position affects visual hierarchy and scanning order.
8. Poor contrast can make text difficult to perceive.
9. Appropriate media supports audience/purpose without imposing unnecessary barriers or technical costs.
10. Creativity can improve memorability, engagement or communication.
11. Unconventional layouts can reduce predictability or usability.
12. SEO means search engine optimisation.
13. Indexing is the processing/storage of page information so it can potentially appear in search results.
14. Keywords help indicate page topic and match user search intent.
15. Updates maintain accuracy, relevance and user trust.
16. Client-side processing occurs on the user's device/browser; server-side processing occurs on the web server.
17. Examples: menu interaction, interface change, client-side validation.
18. Examples: database lookup, authentication, server-generated content.
19. Browser compliance concerns whether features work appropriately across browsers.
20. “Looks good” provides no evidence, mechanism or audience/purpose connection.

## Media-appropriateness guidance

### College autoplay video
Potential strengths: immediate atmosphere and branding. Risks: page weight, mobile data, distraction, autoplay/accessibility issues. A balanced learner answer should judge appropriateness rather than simply reject video.

### Retail product media
Multiple relevant images and a short demonstration video can directly support purchasing decisions. Learners should still consider optimisation and duplication.

### Unrelated animated news banners
Likely to distract and add performance cost without supporting content purpose.

### Information presented only as an image
Potential accessibility problem because essential information may not be available to assistive technologies or users who cannot interpret the image effectively.

### Game promotional site
Rich media may be highly appropriate to the audience and purpose, provided compatibility and performance are managed.

## SEO guidance

Keep explanations at the level supported by the specification. Avoid turning the session into advanced search-engine marketing.

Useful distinctions:

- SEO supports discoverability; it does not guarantee ranking.
- indexing and crawling are related but not identical concepts.
- metadata should accurately describe content.
- relevant keywords are different from excessive repetition.
- updates matter because stale information weakens usefulness and trust.
- limiting crawling can prevent unnecessary/private/duplicate areas being processed.

## Client-side vs server-side guidance

Do not imply that every task belongs exclusively to one side. Modern applications often involve both.

Indicative classifications:

1. menu opens → mainly client-side
2. login checked against stored account data → mainly server-side
3. empty-field warning before submission → client-side
4. database returns vacancies → server-side
5. pointer rollover changes image → client-side
6. basket saved to account → both/client interface plus server persistence
7. live account information → both, with server-side data retrieval and client presentation

## Browser compliance

Learners should understand that a technically valid feature can still create practical problems if browser/device support differs. Encourage them to connect compatibility failures to:

- user frustration
- inaccessible content
- abandoned transactions
- reputational damage
- increased support workload
- lost revenue or engagement

## Progressing from comparison to analysis

A.P1 requires comparison. Week 3 should begin preparing learners for A.M1 by encouraging causal reasoning.

Weak:
> Amazon uses more images than BBC.

Stronger:
> Amazon uses a denser set of product images because its users are frequently comparing items before purchase; this supports the transactional purpose but can also increase visual complexity and page weight.

Do not provide BBC/Amazon sentences like this for learners to submit; use equivalent neutral examples when modelling.

## Adaptive teaching

### Support

- give one concept at a time
- provide feature/effect matching cards
- provide SEO vocabulary definitions for matching
- allow learners to draw client/server diagrams
- use sentence stems linking evidence to effect

### Stretch

- analyse trade-offs
- distinguish technical performance from perceived performance
- explain how organisational impact can arise from compatibility or discoverability problems
- ask learners to challenge over-general claims such as “more media is bad”

## English, maths, EDI and employability

**English:** comparison-to-analysis progression, cause/effect vocabulary, technical precision.

**Maths:** relative proportion and introductory golden-ratio discussion.

**EDI:** colour contrast, readable media, avoiding media-only communication of essential information.

**Employability:** balancing client expectations, user needs, discoverability, compatibility and technical constraints.

## End-of-session diagnostic

Learners are ready for Week 4 when they can explain not just **what** a website does, but **how a particular choice creates an effect and why that matters**.
