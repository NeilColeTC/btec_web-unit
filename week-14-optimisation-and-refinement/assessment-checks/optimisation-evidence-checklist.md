# Week 14 Optimisation Evidence Checklist

Use this before considering an optimisation/refinement complete.

## Evidence trail

- [ ] The issue came from genuine testing, feedback or review evidence.
- [ ] The issue is linked to a requirement, user need or quality concern.
- [ ] The original problem is described clearly.
- [ ] Before evidence has been retained.
- [ ] More than one possible response was considered where appropriate.
- [ ] The chosen change is justified.
- [ ] The implementation change is documented.
- [ ] The original test was repeated under comparable conditions.
- [ ] The retest result is recorded honestly.
- [ ] Related regression checks were completed.
- [ ] Before/after evidence makes the improvement visible.
- [ ] Any trade-off or remaining weakness is acknowledged.
- [ ] A final judgement explains whether the optimisation was successful.

## Quality check

Can another person follow this chain without asking you what happened?

> **evidence → issue → decision → change → retest → judgement**

- [ ] Yes
- [ ] Not yet
