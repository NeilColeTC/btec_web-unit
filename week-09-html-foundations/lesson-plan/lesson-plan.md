# Week 9 Lesson Plan – HTML Foundations

**W/B:** 09 November 2026  
**Duration:** 3 hours  
**Specification focus:** C2  
**Assessment preparation:** C.P4, C.P5

## Learning outcomes

Learners will be able to:

1. Explain the role of HTML in website development.
2. Construct a valid HTML5 page structure.
3. Use semantic structural elements appropriately.
4. Create meaningful heading hierarchy, links, images and lists.
5. Create relative navigation across multiple pages.
6. Explain metadata, page titles and viewport settings.
7. Create accessible basic form controls using labels and suitable input types.
8. Transfer techniques from a teaching exemplar into an independently designed solution.

## Key terminology

HTML, element, tag, attribute, semantic HTML, metadata, `DOCTYPE`, `head`, `body`, `header`, `nav`, `main`, `section`, `article`, `footer`, heading hierarchy, hyperlink, relative path, absolute URL, alternative text, form, label, fieldset, legend, input type, validation.

## Teacher modelling

Keep the first live-code example neutral and small. Model the relationship:

**content meaning → semantic element → browser structure → accessibility/maintainability**

Do not begin with visual appearance. Show that HTML can be structurally strong even when browser-default styling looks plain.

When Stage 1 is introduced, ask learners to explain before you explain. Useful prompts:

- Why might this content be inside `main`?
- Why is the navigation wrapped in `nav`?
- What would happen if the relative path were wrong?
- Does this image's alternative text communicate useful information?
- Why is the contact form understandable before any CSS is present?

## Adaptive teaching

### Support

- provide a partially completed neutral HTML skeleton
- use colour-free printed/tag cards to order document structure
- display a simple folder tree for path tracing
- pair confident/less-confident learners for code reading, then require independent implementation
- use sentence stems: “This element is appropriate because…”

### Stretch

- compare semantic HTML with an equivalent `div`-heavy structure
- explain why multiple `h1`/heading decisions should reflect document meaning
- investigate native input validation (`required`, `type="email"`)
- explain the difference between decorative and informative images
- propose an alternative semantic structure and justify it

## English and mathematics

**English:** precise technical vocabulary, logical explanations, concise page content and meaningful labels/link text.

**Mathematics:** hierarchy/order, nested structures and relative-path reasoning provide light logical/mathematical thinking.

## EDI / British Values / employability

Link semantic structure and labels to inclusive access. Discuss meaningful alternative text without stereotypes or assumptions. Emphasise professional habits: readable code, consistent naming, testing links and implementing from reviewed design documentation.

## Misconceptions to anticipate

- HTML controls visual design
- semantic tags automatically change appearance significantly
- every block of content should be a `section`
- `alt` text should describe every visual detail
- absolute URLs are always preferable to relative paths
- a form with HTML controls automatically stores/submits data successfully
- copying Stage 1 and changing organisation names is acceptable assessed development

## Assessment boundary

Learners may make controlled changes to a temporary Hot Wheels copy for learning. Their assessed implementation must originate from their own reviewed Hot Beans design and show independent code/content decisions.

## After the lesson

Check learners can create a valid page, navigate between at least two pages, explain key semantic choices and identify how their HTML maps back to their own design evidence. Carry any structural misconceptions into Week 10 retrieval.
