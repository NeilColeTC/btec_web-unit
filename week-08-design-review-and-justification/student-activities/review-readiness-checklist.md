# Week 8 – Review Readiness Checklist

Before asking someone to review your design, make sure the reviewer has enough information to give meaningful feedback.

## Requirements

- [ ] The website problem/purpose is clear.
- [ ] The intended audience is identified.
- [ ] Client requirements are recorded.
- [ ] Important inferred user needs are identified.
- [ ] Constraints are recorded.
- [ ] Success criteria are available.

## Structural design

- [ ] Site map is complete.
- [ ] Main navigation is shown.
- [ ] Required pages/content are represented.
- [ ] The intended user journey can be followed.

## Visual design

- [ ] Mood board/style direction is available.
- [ ] Main page wireframes are complete.
- [ ] Important content hierarchy is visible.
- [ ] Navigation and calls to action are identifiable.

## Responsive design

- [ ] Mobile/tablet behaviour has been considered.
- [ ] Navigation changes are shown or explained.
- [ ] Content reflow/stacking is shown or explained.
- [ ] Form usability on smaller screens has been considered.

## Technical design

- [ ] Planned interactions have been identified.
- [ ] Pseudocode/flowcharts are available where relevant.
- [ ] SEO considerations have been planned.
- [ ] Assets and licences have been considered.
- [ ] Data protection/copyright considerations are recorded where relevant.
